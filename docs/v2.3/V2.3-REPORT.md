# LOWTIDE v2.3 — an installed Mac app and a standard MCP server

**Status: PASS**, with the limitations listed below. Built on branch `v2.3`, rehearsed
on a copy of the live data under a separate launchd label, then installed live on
2026-10-07.

## What was built

- **Installed runtime** in `~/Library/Application Support/LOWTIDE` (`runtime/<build>`,
  `current`, `previous`, `launchd/`, `logs/`), independent of the repository: one
  self-contained companion bundle (Node built-ins only) that serves the built app, API,
  live events and MCP on 127.0.0.1:4318.
- **launchd agent** (RunAtLoad, restart on unexpected exit, GUI sessions only, minimal
  environment, own log); Start at login is its copy in `~/Library/LaunchAgents`.
- **LOWTIDE.app** in `/Applications`: reuses or starts LOWTIDE (kickstart, bootstrap),
  waits for health, opens it paired with a one-time code; alerts on failure.
- **`npm run build:lowtide`** and **`npm run install:lowtide`** (rehearse on a backup
  copy, switch, timed handover to launchd, verify, roll back on failure).
- **MCP on the official TypeScript SDK** 1.32.1: Streamable HTTP, sessions per grant, one
  registry for HTTP and the bundled stdio bridge (which can start LOWTIDE), truthful
  annotations, needs in descriptions, typed schemas, concise capabilities, new server
  instructions.
- **Health** (`/api/health`), an integrity check at startup, one instance per data
  folder, safe port ownership, Settings for the runtime, app, MCP and ChatGPT status.

## Verified

- Rehearsal: first install over a running v2.2 companion, an update (current/previous),
  a failure after the switch (links and agent put back, running LOWTIDE untouched),
  `kill -9`, second starts (exit quietly), a stale lock, a port held by another program
  (named, not touched), LOWTIDE.app running/stopped/missing runtime, a simulated login,
  a database locked for 2 s during an MCP write (waited, succeeded), live events after
  an MCP write, zero files open on the external volume, MCP Inspector (connect,
  initialize, tools/list without portability warnings, reads, creates, decision,
  refusal, invalid and revoked tokens, ambiguity, Protected Time), and a real browser
  (pairing, every main page, no console errors or CSP violations, the unpaired screen).
- Live: check-only rehearsal on a fresh backup, the install, launchd owning the process
  from the installed runtime, health ok on every check, counts unchanged, app, MCP and
  live events, Claude Code reconnecting through its stdio bridge (version 2.3.0, its
  grant and 114 tools), a live `kill -9` restarted by launchd, LOWTIDE.app, and a
  headless browser session on the live data.

## Tests

84 files, 794 tests (from 77 and 760). Typecheck, lint, Prettier and the builds are
clean. Across the session's full-suite runs, three heavy UI tests (Command Room
roadmap, companion integration, Sleep Mode) each failed once under load and passed
alone and on rerun; the final full runs passed 794/794.

## Limitations

- ChatGPT is prepared (HTTP endpoint, grant, docs) but not tested: it needs a tunnel the
  owner sets up, and LOWTIDE has no OAuth.
- A real restart of the Mac wasn't performed; a login was simulated.
- The runtime uses the Mac's Node (22.22 or later); LOWTIDE.app is signed ad hoc.
- Live startup is slower than in the rehearsal (about 3.3 s versus 1.2–1.5 s); it hasn't
  been profiled.
- Claude Code's existing configuration still points at the repository's bridge (it
  keeps working while the volume is mounted); moving it to the installed bridge is one
  command (docs/integrations/CLAUDE-MCP.md).
